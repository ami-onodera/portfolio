One template, many brands

Three different refer-a-friend portals, a single template. The page structure stays the same for every brand; each one brings its own assets, copy, logo and design identity. It’s how I build real portals: brand styling set in a Material UI theme and managed in a headless CMS.

Role
Web designer, from UI design to code implementation
Context
B2B referral portals for brands in telecom, energy, banking, insurance and more
Tools
Contentful, Figma, Material UI theme JSON, HTML/CSS, vibe coding with Claude
Note
Brands shown are fictional, built to show the system without exposing client work

The three brand portals

The challenge

Every partner brand needs a referral portal that feels like their own: their styling, their assets, their tone of voice. Their customers should never feel they have left the brand.

At the same time, the platform has to ship every portal from one codebase and one content model, and it has to ship fast. A bespoke build per brand would be slow to deliver, hard to QA and impossible to maintain. So the question becomes: how much can change, and where exactly should it change?

The approach

I treat a brand as a set of design decisions, not a set of pages. I read the brand guidelines and the assets the client provides, turn them into a small set of style elements, and let the template render the page. Layout, components and interactions are designed once, in Figma and in CSS; each brand only brings its own values.

  1. 1

    Brand guidelines

    Colours, typefaces, CTA style, visual assets and tone of voice, taken from the brand’s own materials.

  2. 2

    Style elements

    Those decisions become a small set of values: colours, fonts, weights and border radius, designed in CSS and set in Material UI theme JSON in production.

  3. 3

    Rendered page

    The shared template reads those values and renders the portal. No new markup, no new components.

What stays fixed, what changes

Designed once

Stays fixed

  • Page layout
  • Section designs: hero, how it works, products, rewards
  • Components: referral card, step, product tile, rewards table
  • Accessibility: headings, labels, focus states
  • Interaction: the referral widget, where users add their email and get their personal link, plus copy link and show more
Per brand

Changes

  • Colours
  • Typefaces and weights
  • Border radius
  • Copy and reward values
  • Order of page sections, interchangeable per brand
  • Logo
  • Assets

Details that make it feel native

Contrast checked per brand

I check every brand’s button and sticker text against WCAG AA. Orbeo’s coral fails with white text, so the sticker uses the brand’s dark ink instead and the coral stays bright.

Designed around client assets

Each brand provides its own imagery and logo. I place and crop them so the brand leads and the referral widget stays clear and readable on top.

Mobile first, fully responsive

Referral links are often opened on a phone, so I design mobile first and check every layout across breakpoints, from small phones to wide desktop screens.

Shared template, separate campaigns

The design template is shared, but in Contentful every portal keeps its own copy, values and settings, so each brand can run its own campaigns independently.
