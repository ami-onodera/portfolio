Designing the content model

A referral portal is not one page in a CMS. It is a tree of nested entries, from the promotion at the top down to each reward row. How that tree is shaped decides what editors can change, what stays consistent, and how fast a new brand goes live.

Role
Web designer: content structure, CMS configuration, theming and CSS styling
Context
B2B referral portals assembled from nested CMS entries
Tools
Contentful, JSON, HTML/CSS, vibe coding with Claude
Note
Fictional brand. The structure mirrors production work, with readable labels instead of internal field names

Interactive x-ray view

Why it matters

Many design decisions never show up in a Figma file. They live in the content model: what an editor can change, what is locked, what repeats, what is optional. If the model is wrong, the design breaks the first time someone edits it.

So I design the structure as carefully as the screens. A good model gives editors, developers and designers the same map of the page, and it lets one template serve many brands without special cases.

  • One shared map

    Editors, developers and designers point at the same entries and use the same names.

  • Reorder without code

    The index page holds an ordered list of sections, so a promotion can reorder or drop sections in the CMS.

  • One Theme entry reskins everything

    Colours, type and border radius sit in a single Theme entry. Swap it and the whole portal changes brand.

My role in this

At Aklamio I work hands-on in Contentful: building and wiring up entries, writing JSON configuration, theming with Material UI, styling in CSS, and running design QA before each release. I care about release readiness as much as the visuals, because a portal is only finished when the content behind it is right.

This is not new ground for me. As Project Manager at Language International I ran the website content in the CMS and a custom CRM, and supervised the translation of the full site into 27 languages. That taught me early that structure is what makes content scale.

Principles I design by

1

Readable labels for editors

Fields are named for the person filling them in, not for the code. “Reward sticker” beats an internal key every time.

2

One source of truth per value

A brand colour lives in the Theme, once. Nothing is copied into sections where it can drift out of sync.

3

Optional is explicit

If a section or field can be left out, the model says so, and the page still looks finished without it.

4

Structure before styling

I agree the entries and their order first. Styling then sits on a stable base instead of patching around content.
